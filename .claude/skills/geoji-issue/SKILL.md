# geoji-issue

이슈는 **아직 안 고친 것**을 적는다. PR 은 **이미 한 변경**을 적는다. 둘의 형식이 다른 이유가 이것뿐이고, 여기서 갈리는 것이 제목이다.

## 제목

- **커밋·PR 의 `type(scope):` 접두사를 쓰지 않는다.** `fix:`·`refactor:`·`feat:` 로 시작하지 않는다. 그 형식은 "무엇을 했다" 는 변경의 요약이라 아직 안 고친 문제에 붙으면 이미 고쳐진 것처럼 읽힌다
- **증상이나 현상을 평서문으로** 적는다. 해결책이 아니라 문제를 적는다
- 한 줄로 읽고 무슨 일인지 알게 한다. 대략 60자 안. 더 필요하면 `—` 로 잇는다
- 종류는 제목이 아니라 **라벨**로 표시한다

```
❌ fix: 돈 예산에 시간 예산의 reserve_after 가 없어 서기가 검수관 몫을 안 남기고 쓴다
✅ 돈 예산에 선점 규칙이 없어 서기가 검수관 몫을 안 남기고 쓴다

❌ refactor: _settle_backend_error 복제 제거
✅ _settle_backend_error 가 핸들러 세 곳에 복제돼 있다

❌ 판결문 이상함
✅ 서기 hell 초안이 SCHEMA_INVALID 로 두 번 떨어져 판결 전체가 TEMPLATE 이 된다
```

계획서 작업이면 카드 번호를 앞에 둔다. `02 CT-01 큐 claim·lease`.

## 본문

양식은 `.github/ISSUE_TEMPLATE/` 에 있다. 웹에서 열면 GitHub 이 붙여 주지만, `gh issue create` 로 만들 때는 이 스킬이 직접 맞춘다.

| 양식 | 쓰는 때 | 라벨 |
| --- | --- | --- |
| `1-bug.yml` 🐛 | 코드가 계획서·계약과 다르게 동작 | `bug` |
| `2-ops-incident.yml` 🚨 | 운영에서 서비스가 제 역할을 못 함 | `ops` |
| `3-task.yml` 🧩 | 계획서 카드·절을 코드로 | `task` |
| `4-docs.yml` 📄 | 문서가 사실과 다르거나 빈칸 | `documentation` |

섹션 제목에 이모지를 하나 붙인다. 목록에서 눈으로 찾기 쉬우라고 두는 것이라 한 섹션에 하나만 쓴다.

| 섹션 | 이모지 | 내용 |
| --- | --- | --- |
| 어디서 | 📍 | 운영(EC2) / 로컬 / CI. 운영이면 시각과 `job_id`·`trace_id` |
| 무엇이 어긋나나 · 무엇이 보였나 | 💥 | 관찰한 사실. 추측을 섞지 않는다 |
| 왜 이렇게 되나 | 🔍 | 코드 근거. 파일과 줄번호 |
| 왜 문제인가 | ⚠️ | 이 버그가 무엇을 망가뜨리나 |
| 로그 | 🧾 | 이벤트 한 줄이면 대개 충분하다 |
| 기대 | ✅ | 무엇이 되어야 하나. 방향이 여럿이면 후보와 판단 근거 |
| 환경 | 🏷 | 이미지 태그 · `prompt_bundle_version` · 기준 커밋 |
| 곁가지 | 🧩 | 본류는 아니지만 같이 본 것 |
| 관련 문서 | 📄 | 번호와 절 |

빈 섹션은 만들지 않는다. 모르는 것은 **모른다고 적는다.**

## 근거

- **추정은 추정이라고 적는다.** "…로 보인다", "확인이 필요하다". 확인하지 않은 것을 사실처럼 적지 않는다
- 코드를 가리킬 때는 `graphs/sentencing.py:1033` 처럼 파일과 줄번호로
- 문서는 번호로 부른다. `10 §16.1`, `01 부록 A`, `runbook §4`
- 로그를 붙일 때 **원문(사유·댓글·판결문)과 비밀값은 뺀다.** 코드·해시·개수만 남긴다(08 §3.3)
- 운영 이슈면 이미지 태그와 번들을 적는다. 그것 하나로 원인이 갈린 적이 있다

## 라벨

만들 때 반드시 하나 이상 단다. `gh issue create --label`, 이미 있는 이슈는 `gh issue edit --add-label`.

| 라벨 | 뜻 |
| --- | --- |
| `bug` | 동작이 계약·명세와 다르다 |
| `ops` | 운영·배포·인프라 |
| `task` | 계획서 카드 구현 |
| `documentation` | 문서가 사실과 다르다 |
| `refactor` | 구조 정리. 동작은 그대로 |
| `prompt` | 프롬프트·판결 품질 |

겹치면 여러 개 단다. 프롬프트가 원인인 버그는 `bug` + `prompt`.

라벨이 저장소에 없으면 `gh label create <이름> --description "<설명>" --color <hex>` 로 먼저 만든다.

## 하지 않는 것

- **이슈를 대신 닫지 않는다.** 닫는 것은 사용자가 한다
- 계획서(`docs/plans/`)의 카드 체크·결정 기록을 이슈에서 대신하지 않는다. 그것은 계획서에 적고 이슈는 가리키기만 한다
- 백엔드가 할 일을 이슈로만 남기지 않는다. 전달 문서 §0 체크리스트가 정본이다(`backend-contract` 룰)
- 하나의 이슈에 두 문제를 담지 않는다. 원인이 다르면 나눈다
