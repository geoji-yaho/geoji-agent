## 확인된 문제와 의미

1. **기각 판결의 AI 문구가 최종 저장되지 않았다.** 검수 단계에 `SCHEMA_INVALID`와 `EVAL_FAILED:GLOBAL:CHECK_FAILED` 로그가 남았고, 백엔드는 `TEMPLATE_READY`/`EVAL_FAILED`로 저장했다. ‘64잔 대신 운동화’는 서기 초안이며 사용자에게 공개된 최종 문구가 아니다. 최종 문구는 ‘기각 / 배심원단이 구매를 기각했습니다.’이고 밈은 null이다. 검수 원본 무효 응답은 캐시에 없어서 정확한 위반 필드까지는 이번 자료로 확정할 수 없다.
2. **심문관(intake)은 5/5 `INVALID_OUTPUT` 폴백이었다.** 외부 호출은 완료됐지만 로컬 출력 검증을 통과하지 못했다. 판결 생성은 폴백 경로를 통해 계속 진행했다. 저장 성공률과 별개로 응답 계약 점검이 필요하다.
3. **순한맛 환산 대상이 잘못됐다.** 근거 F0는 ‘지하철 기본요금 1,400원 기준 약 8회분’인데 결과는 ‘택시 8회분’이다. 검수는 통과했으므로 의미상의 단위 오류를 놓쳤다.
4. **승인 문구가 승인 취지와 어긋난다(사람 평가).** 고장 난 업무용 키보드 교체를 승인했는데 ‘연말 잔고 0원 예언’으로 비난한다. 승인용 서기 톤을 따로 검토할 필요가 있다.
5. **지옥맛의 강도 구분이 약하다(이번 표본의 사람 평가).** ‘실력은 그대로고 잔고만 22잔어치 증발했네.’는 매운맛과 확연한 차이가 보이지 않는다. ‘99k’ 영문 금액 축약도 노출된다. 사례당 1건이므로 전체 품질의 통계적 결론은 아니다.
6. **유죄 3건의 밈이 반복된다.** 모델 초안의 태그가 HEAVY인 경우도 최종 형량 `oneDay`에 따라 LIGHT로 교정됐다. 로컬 카탈로그의 `GUILTY_LIGHT` 후보가 1장뿐이어서 최근 노출 감점 후에도 ‘실망’ 이미지가 선택됐다. 선택 계산과 DB ID는 일치한다.
7. **이미지 없는 기각 카드의 금액 줄바꿈.** 모바일 390px 화면에서 ‘289,000’과 ‘원’이 분리돼 두 줄로 표시된다. PNG 생성 자체는 성공했다.

## 판결 화면과 공유 카드가 다른 이유

승인·순한맛·지옥맛의 문장은 F0를 인용하고 그 근거의 DB 공개 범위는 `ROOMS`였다. 백엔드 `ShareCardAssembler`는 모든 인용 근거가 `PUBLIC`이어야 AI 문구를 공유 카드에 유지한다. 그렇지 않으면 본문과 제목을 기본 문구로 바꾼다. 따라서 세 사례는 카드 제목이 ‘동의/유죄’로 바뀌었다.

매운맛 문장은 근거 인용이 없는 의견(`evidence_labels=[]`)이라 제목이 그대로 남았다. 이 차이는 현재 구현의 동작이며 이번 테스트에서 공개 범위나 필터를 변경하지 않았다.

현재 프론트 PNG는 제목·금액·형량·밈을 그리며 판결문 본문은 그리지 않는다. 공유 카드에 AI 문구가 보이지 않는 현상을 생성 실패와 구분해야 한다.
