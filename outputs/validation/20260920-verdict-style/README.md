## 사람 검토에서 발견한 문제

1. 막차 종료 후 택시: 세 강도 모두 불가피한 사정을 제대로 인정하지 못함. 과소비 단정·퇴근시간 관리 책임·회사 숙박 대안에 근거가 없음.
2. 늦잠 택시: 사유 관련성은 있으나 지옥맛도 알람 조언으로 끝나 강도 차이가 약함.
3. 충전기 교체: 받은 매운맛은 필요성을 인정함. 순한맛·지옥맛은 타임아웃이라 비교 불가.
4. 색상 추가 구매: 불필요한 추가 구매를 짚지만 매운맛은 49,000원을 5만 원으로 반올림했고 지옥맛은 내부 값 `disagree`가 노출됨.
5. 12k·49k·12천 원 같은 부자연스러운 금액 표현이 반복됨.

## v6.1 후속 보완

- 같은 호출 안에서 `case_reading`(사유 인용·인정할 사정·놀릴 선택)을 먼저 출력. 공개 계약에는 포함하지 않고 새 사실로 저장하지 않음.
- 유죄라도 사유를 거짓이나 과소비로 간주하지 않도록 명시. 타깃이 없으면 null로 두며 억지 비난을 만들지 않음.
- 지옥맛을 생활지도만으로 끝내지 않도록 보완. 금액은 한국어 표기·원금액 유지.
- 내부 평결/기법 코드 노출을 서버 검증에서 감지하여 기존 재작성 경로로 처리.
- `투자해`의 `자해` 부분 문자열 오탐 수정. 별도의 자해 단어는 계속 차단.

## 무료 검증과 재실행

계약·단위 테스트 결과는 docs/plans/20-natural-verdict-style.md에 기록한다. 아래 dry-run은 실제 문구 품질을 평가하지 않는다.

```bash
uv run scripts/probe_verdict_cards.py --case 0 --out /tmp/taxi-late-dry.json
uv run scripts/probe_verdict_cards.py --case 6 --out /tmp/taxi-last-transit-dry.json
uv run scripts/probe_verdict_cards.py --case 7 --out /tmp/charger-replacement-dry.json
uv run scripts/probe_verdict_cards.py --case 8 --out /tmp/charger-color-dry.json
```

새 유료 승인을 받은 뒤 각 명령에 `--execute`를 추가하면 사건당 3회 호출한다. 모델 교체 시 같은 입력으로 비교하고 품질·지연·비용·타임아웃을 함께 기록한다.

골든셋 50건 FakeLLM 실행도 완료했으나 고정 택시 fixture를 모든 사건에 재사용하므로 expect 51건·제목 중복 1건이 실패하고 judge는 고정 3점이다. 실제 의미 품질 통과가 아니다. 형식·길이·근거 라벨·어휘·평결 태그 검사는 오류 0건이었다.

실제 Postgres 통합 테스트와 운영 배포는 수행하지 않았다. 외부 API·DB 스키마·모델 기본값은 유지했다.
