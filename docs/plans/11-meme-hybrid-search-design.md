# 짤 생성·등록 및 하이브리드 검색 설계

상태: 2026-09-11 사용자와 제품 방향 합의. 이 문서는 구현 기준 설계이며, 기존 API·DB 계약과 실행 코드는 아직 변경하지 않았다.

## 1. 목적과 범위

판결문 생성 시 어울리는 이미지의 상황·반응·키워드를 함께 출력하고, 추가 생성형 LLM 호출 없이 벡터 검색과 키워드 검색으로 짤을 선택한다. 검색 문장 임베딩 계산은 별도로 필요하며, 판결 생성 작업당 계산해 재사용한다.

초기에는 사용자가 Codex의 b-meme 스킬로 이미지를 미리 생성하고 검수한 뒤 등록한다. 향후 서버 작업자가 사용자 제공 이미지 또는 사용 허용된 출처의 밈을 수집·분석·필요시 변환하고 같은 등록 경로를 이용한다. 지금 구현 범위에 무인 수집·생성 서버는 포함하지 않는다.

자유 설명과 검색 태그의 값은 고정 enum으로 제한하지 않는다. 필드 이름·타입·길이·버전 및 사용 가능 상태·접근 권한·판결 용도는 구조화한다.

## 2. 현재 구현과 달라지는 점

- `skills/b-meme/scripts/save_metadata.py`: 감정·키워드·컷별 설명·자막 및 해시를 로컬에 저장한다. 전체 설명·사용 맥락·등록 상태·임베딩은 없다.
- `src/geoji_ai/contracts/writer.py`: `meme_tag`, `meme_hints`를 제공한다. 현재 감정은 문자열이고 키워드는 최대 10개다. 스킬의 키워드 상한 5개와 차이가 있다.
- `10-backend-contract.md` §11: 태그 필터 및 고정 가중치 선택 명세가 있다. 이 문서는 그 검색 부분을 대체할 설계이며 즉시 실행 계약을 바꾸지 않는다.
- 업무 테이블의 최종 저장은 백엔드 API 책임이다. 스킬이나 AI 워커가 업무 DB에 직접 쓰지 않는 기존 경계를 유지한다.

## 3. 책임 분리

| 구성 요소 | 책임 |
|---|---|
| b-meme 스킬 | 이미지 생성, 실제 결과 관찰, 설명·검색 태그·용도 제안, 로컬 기록 |
| 사용자 | 자막 정확성, 사용 맥락, 출처·공개 범위, 판결 용도 검수 |
| 등록 도구 | 로컬 검증, 관리자 인증, 업로드와 등록 요청, 중단 후 재개 |
| 백엔드 | 권한·메타데이터 검증, 객체 키 발급, DB 저장, 검색 가능 상태 관리 |
| 임베딩 처리 | 등록 문서·판결 검색 문장 임베딩, 버전 기록, 제한된 재시도 |
| 검색 모듈 | 권한 필터, 두 검색 결과 결합, 반복 노출 반영, 선택 근거 기록 |

독립 Agent 서버나 LangGraph 도입은 초기 필수 조건이 아니다. 산출물 계약과 등록 경계를 먼저 분리해 호출 주체를 교체할 수 있게 한다.

## 4. 이미지 메타데이터

다음은 신규 메타데이터 버전의 논리 필드다. 물리 테이블과 API 경로는 별도 백엔드 저장소 확인 후 정한다.

| 필드 | 의미 및 검증 기준 |
|---|---|
| `schema_version` | 기존 로컬 v1과 구분되는 신규 버전 |
| `asset_id`, `asset_version` | 서버 발급 식별자와 변경 불가능한 이미지 버전 |
| `description` | 실제 관찰한 전체 장면, 비어 있지 않은 문자열, 최대 1,000자 |
| `usage_context` | 어떤 상황·반응에 쓰는지에 대한 해석, 최대 1,000자 |
| `tags` | 자유 문자열 최대 20개, 항목당 40자, 공백 제거·Unicode NFC 정규화·중복 제거 |
| `panels` | 컷 순서, 표정·포즈·실제 자막. 전체 반전은 usage_context에 설명 |
| `allowed_verdict_tags` | 사용자가 승인한 기존 MemeTag 5종의 부분집합. 빈 배열은 검색 비활성 |
| `review_status` | pending / approved / rejected |
| `visibility`, `owner_id` | public / private 및 접근 주체. 서버가 권한으로 검증 |
| `source_type`, `source_url` | 생성·사용자 제공·외부 출처 구분 및 원출처. 알 수 없는 출처를 추측하지 않음 |
| `publication_approved` | 출처와 공개 가능 여부 확인. 공개 검색 활성화 조건 |
| `uncertainties` | 자막 판독·용도 해석 등의 불확실성. 남아 있으면 자동 승인하지 않음 |
| `asset_sha256`, `mime_type`, `width`, `height` | 실제 파일에서 계산·검증 |
| `metadata_version`, `embedding_model`, `embedding_version` | 설명 수정·모델 변경과 검색 인덱스의 일치 확인 |

기존 감정·지출 카테고리·subject는 보조 필드로 보존할 수 있으나 자유 태그를 그 enum으로 제한하지 않는다. 지출 종류는 의상이나 돈이 없다는 자막만으로 추정하지 않는다.

예: description은 “작은 초록 캐릭터가 거대한 지갑 안을 들여다보며 당황한다”, usage_context는 “돈을 다 쓴 사실을 믿기 싫거나 예상 밖 지출에 당황할 때”, tags는 `[지갑, 돈없음, 당황, 현실부정]`다. 관찰 사실과 해석을 구분한다.

이미지 1장을 검색 문서 1개로 취급한다. `description → usage_context → 컷 순서의 captions → tags`를 필드 라벨과 함께 결합한 텍스트를 임베딩하고, 검색 텍스트 해시도 저장한다. 제외 조건이나 긴 실행 프롬프트는 긍정적 검색 텍스트에 섞지 않는다.

## 5. 판결 생성 응답

기존 판결 생성 호출에서 최종 판결문에 맞춰 다음 검색 정보를 함께 만든다.

```json
{
  "meme_query": {
    "situation": "반복된 배달 주문으로 예산을 소진했다",
    "desired_reaction": "텅 빈 지갑을 보고 현실을 부정하는 우스운 당황",
    "keywords": ["배달", "과소비", "지갑", "현실부정"]
  }
}
```

situation과 desired_reaction은 각각 비어 있지 않은 최대 300자 문자열, keywords는 최대 10개·항목당 40자로 제안한다. 감정은 사용자의 실제 정신 상태가 아니라 카드가 전달할 반응이다. 서버의 확정 평결·형량을 검색 힌트가 변경할 수 없다.

강도별 판결문이 다르면 해당 TextDraft별 검색 정보를 생성·연결한다. 현재 상위 meme_hints 1개와 단일 meme_image_id 구조는 이 요구를 표현하지 못하므로, 강도별 텍스트·선택 이미지 저장 변경을 백엔드와 함께 적용한다. 같은 강도·텍스트 버전에서는 이미지를 고정한다.

임베딩은 finalize 트랜잭션 이전에 완료한다. 본문·검색 정보가 수정되면 검색 임베딩도 무효화한다. 검색 정보 오류로 판결문 자체를 폐기하지 않고 기존 힌트나 결과별 기본 이미지로 대체한다.

## 6. 등록과 저장

S3에는 이미지와 접근 제한된 생성 기록을 저장한다. DB는 검색 메타데이터와 승인 상태의 정본이다. 객체 키는 `memes/{asset_id}/{asset_version}/image.{extension}` 형식으로 제안하며 승인된 버전을 덮어쓰지 않는다. 원본 입력·상세 프롬프트는 공개 이미지 경로와 분리한다.

등록 상태는 `RESERVED → UPLOADED → INDEXED → READY`로 진행한다. 검수 상태는 별도 관리하며 approved, publication_approved, 접근 범위와 판결 용도가 갖춰진 자산만 READY로 전환한다. 삭제 시 상태와 무관하게 검색을 즉시 차단한다.

1. 로컬에서 파일·메타데이터를 검증하고 업로드 전에 지속 가능한 요청 ID를 기록한다.
2. 관리자 API가 요청 ID로 자산을 예약하고 제한된 객체 키의 업로드 URL을 발급한다.
3. 등록 도구가 파일을 올리고 서버에 완료를 요청한다.
4. 서버가 실제 객체·해시·형식·크기를 확인하고 메타데이터를 저장한다.
5. 임베딩을 생성해 해당 metadata_version과 함께 저장하고 검색 가능 상태로 전환한다.

S3와 DB 전체를 단일 트랜잭션으로 간주하지 않는다. 각 단계 완료 상태를 저장해 실패한 단계만 재시도한다. 타임아웃은 성공 여부부터 조회한다. 만료된 업로드 URL은 같은 예약에 대해 재발급한다. DB 실패 후 이미지를 다시 생성하지 않는다. 동일 소유자·해시·버전 중복을 막되 다른 사용자의 비공개 자산 존재를 노출하지 않는다.

임베딩이 실패한 신규 자산은 비활성 상태로 남긴다. 관리자는 미완료 자산을 조회·재개할 수 있다. 기존 활성 자산의 설명 변경은 새 메타데이터·벡터 쌍이 준비된 뒤 함께 전환한다. 권한 철회·삭제는 재색인 완료를 기다리지 않는다.

## 7. 검색과 선택

저장소 계획의 Supabase/PostgreSQL을 우선 활용하고 pgvector와 키워드 검색 조합을 검증한다. 현재 개발용 postgres:16 이미지에는 확장 설치를 별도로 확인해야 한다. 전용 벡터 DB는 이 단계에서 도입하지 않는다.

1. READY·승인·접근 허용·비삭제·판결 용도 일치를 벡터와 키워드 검색 양쪽에 적용한다.
2. situation과 desired_reaction을 중심으로 구성한 검색 문장을 등록 문서와 호환되는 모델로 임베딩한다.
3. 벡터·키워드 각각 상위 후보를 조회한다. 첫 평가 설정은 각각 20개이며 운영 상수가 아니라 조정 대상이다.
4. 이미지 ID로 합치고 `sum(1 / (60 + rank))` RRF로 정렬한다. rank는 1부터 시작하고 미등장 검색의 기여는 0이다.
5. 초기에는 관련도 상위 5개에서 최근 노출되지 않은 첫 후보를 선택한다. 모두 최근 노출이면 관련도 1위를 유지한다. 동점은 post_id·image_id 기반 고정 순서로 결정한다.
6. 최종 저장 직전에 접근·활성 상태와 버전을 재검증하고 텍스트 버전·강도에 이미지 ID·버전을 연결한다.

RRF 점수는 절대 적합도나 확률이 아니다. 후보가 있어도 부적절할 수 있으므로 벡터 거리·키워드 근거·검수 결과를 평가셋에서 비교해 폴백 기준을 정한다. 기준 검증 전에는 기존 선택기를 교체해 운영 활성화하지 않는다. 임베딩/벡터 장애는 키워드 검색으로, 후보 부재·검색 시간 초과는 결과별 기본 이미지로 전환한다.

한국어 키워드 검색은 우선 자유 태그의 정규화 일치와 텍스트 검색을 비교 검증한다. PostgreSQL 기본 전문 검색만으로 한국어 형태소·신조어 문제가 해결된다고 가정하지 않는다. FTS를 BM25라고 부르지 않으며 형태소 처리·부분 일치 확장은 별도 평가 후 선택한다.

자막의 반대 의미는 임베딩만으로 확실히 배제할 수 없다. 초기에는 사람이 판결 용도를 승인하고 평가셋에서 모순 사례를 검사한다. 자동 등록 단계에서도 이 제약은 유지한다.

## 8. 비용·지연·관측·보안

- 이미지는 등록 시 한 번 생성하고, 임베딩은 문서 버전당 한 번 계산한다. 판결 검색 임베딩은 동일 텍스트 버전에서 재사용하며 새로고침은 재검색하지 않는다.
- 타임아웃·일시 실패에 한해 제한된 재시도를 적용한다. 생성 재시도, 업로드 재시도, 임베딩 재시도를 별도로 기록한다. 사용자별·일별 생성 예산과 호출 한도는 자동화 배포 전 필수 설정이다.
- 실행 ID, 처리 단계, 실패 원인, 임베딩 모델·버전, 단계별 지연, 토큰·비용, 후보 수, 각 검색 순위, 선택 이유, 폴백 사유를 기록한다. 키·업로드 URL·개인정보가 담긴 원문은 일반 로그에서 제외한다.
- 외부 이미지·자막·메타데이터는 신뢰하지 않는 입력이다. 이미지 속 명령을 도구 지시로 실행하지 않는다. 미래 URL 수집기는 허용 출처·다운로드 크기·실제 형식·내부망 접근 차단을 검증한다.
- 미승인·비공개 사용자 이미지가 전역 검색에 섞이지 않도록 양쪽 검색과 최종 저장에 권한 검사를 둔다. 삭제·비공개 전환은 캐시와 이미 저장된 카드의 접근에도 반영하며 대체 이미지를 제공한다.
- 최신 유행이라는 이유만으로 자동 공개하지 않는다. 출처·사용 허용·민감 정보 검수 상태를 보존한다.

## 9. 평가와 완료 조건

초기 평가셋은 실제 판결 30개와 승인 이미지 묶음으로 구성한다. 각 판결에 적절한 이미지 집합·부적절한 이미지·기본 이미지가 나은 경우를 사용자가 표시한다. 판결 용도·자막 반대 의미·동의어·빈 후보·반복 노출 사례를 포함한다.

- 자유 키워드만 / 벡터만 / 하이브리드의 같은 평가셋 결과를 비교한다.
- Recall@5, 최종 적합 선택률, 자막 모순 선택 수, 폴백 비율, 반복 노출률, p50/p95 검색 지연, 판결당 임베딩 비용을 보고한다.
- 운영 전환 조건: 초기셋에서 접근 권한 위반 및 표시된 자막 모순 선택 0건, 최종 적합 선택률이 기존 방식 이상. 작은 표본의 한계를 명시하고 실제 운영에서도 추적한다.
- 업로드 성공 후 DB 실패, 임베딩 실패, 중복 요청, 만료 URL, 중간 중단, 메타데이터 변경, 권한 철회·삭제 경합을 검증한다.
- 등록된 이미지의 해시·설명·검색 문서·임베딩 버전 일치를 검사한다. 생성 자체 실패와 등록 실패를 구분한다.

## 10. 구현 단위와 영향 범위

1. **로컬 산출물 확장**: b-meme 스킬·분류 스크립트·테스트에 description, usage_context, 자유 tags와 버전 검증을 추가한다. 기존 v1 산출물 읽기·변환을 지원하고 원본 파일은 보존한다. 별도 상세 실행 계획의 첫 대상이다.
2. **백엔드 등록**: 실제 백엔드 저장소의 migration·인증·S3 구성을 확인한 뒤 관리자 API와 등록 도구를 구현한다. AI 업무 테이블 직접 쓰기는 추가하지 않는다.
3. **판결·검색 계약**: writer/finalize/공개 view와 정본 JSON schema, 생성기, fixtures, fake provider, 동등성 테스트 및 문서 01·08·10을 함께 갱신한다. 신규 소비자가 준비되기 전 기존 응답 필드를 제거하지 않는다.
4. **검색 평가·전환**: 승인 이미지로 벡터·키워드·RRF를 비교하고 폴백 기준을 확정한다. 전환 실패 시 기존 선택기로 되돌릴 수 있게 한다.
5. **서버 자동화**: 운영 수요가 생기면 큐 작업자가 같은 산출물·등록 계약을 사용한다. 수집·생성 예산, 공개 승인 정책, 실패 재개를 먼저 갖춘다.

이번 문서는 DB schema, public API, build/CI, 외부 저장소를 변경하지 않는다. 모델·차원·키워드 엔진·실제 API 경로는 위 단계의 환경 확인과 평가로 선택하며, 확정되지 않은 값을 운영 코드에 하드코딩하지 않는다.
