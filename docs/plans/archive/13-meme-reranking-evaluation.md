# 판결문·짤 리랭킹 모델 비교 실험

> 11 §7·§9의 후속 실험 설계. 2026-09-11 공식 모델 카드 확인. **실측 결과나 모델 채택 결정이 아니다.** 이번 구현은 로컬 메타데이터 v2까지이며 아래 모델 실행기와 실제 평가 데이터는 아직 없다.

## 1. 무엇을 최적화할 것인가

지출 단어가 비슷한 이미지를 고르는 것만으로는 부족하다. 최종 판결문의 상황·웃음의 방향·원하는 반응에 맞고 자막이 판결 취지를 뒤집지 않는 이미지를 골라야 한다. 예를 들어 배달 과소비를 꼬집는 판결에 배달 사진보다 빈 지갑을 부정하는 캐릭터가 더 적절할 수 있다. 판결 용도/접근 권한은 모델 점수로 완화할 수 없는 필터다.

임베딩은 후보를 찾고 리랭커는 찾은 후보의 순서를 다시 정한다. 리랭커는 후보에서 빠진 정답을 복구하지 못한다. 따라서 후보 Recall과 최종 선택을 분리해서 평가한다. RRF는 순위 결합 계산식이며 학습된 리랭킹 모델이 아니다.

## 2. 비교 후보와 우선순위

| 실험군 | 입력 | 검증하려는 것 |
|---|---|---|
| 현재 고정 가중치 선택기 | 현재 계약의 태그·전략·감정·키워드 | 반드시 유지할 제품 기준선 |
| 자유 태그 / 벡터 / RRF | 동일 승인 코퍼스, 동일 판결 query | 후보 검색과 결합 자체의 효과 |
| BAAI/bge-reranker-v2-m3 | 판결 query + 이미지 검색 문서 | 다국어 텍스트 cross-encoder 기준선 |
| Qwen/Qwen3-Reranker-0.6B | 같은 텍스트 쌍 + 고정 작업 지시 | 상황·반응 중심 지시의 효과 |
| Qwen/Qwen3-VL-Reranker-2B | 같은 query + 실제 이미지 + 동일 검색 문서 | 텍스트 설명에서 빠진 표정·자막·컷 반전의 효과 |
| Qwen/Qwen3-Reranker-8B 또는 Qwen3-VL-Reranker-8B | 각각 같은 입력 | 작은 모델이 부족할 때 품질·자원 증가 비교 |
| Cohere rerank-v4.0-fast / pro (선택) | 같은 텍스트 쌍 | 로컬 모델 운영 대신 관리형 API를 쓸 때 품질·비용 비교 |

**먼저 BGE-v2-m3와 Qwen3-0.6B를 비교하고, 자막·표정 오류가 남으면 VL-2B를 추가한다.** 이미지 직접 이해가 중요한 이 문제에서 VL-2B는 특히 검증할 가치가 있다. 다만 한국어 밈 평가 전에는 가장 좋은 모델이라고 단정하지 않는다. 공개 일반 검색 벤치마크는 이 제품의 정답표를 대체하지 않는다.

BGE와 Qwen 텍스트 리랭커는 이미지 픽셀을 보지 않는다. 설명·OCR가 틀리면 그 오류가 그대로 전달된다. VL은 이미지와 텍스트를 함께 입력할 수 있지만 한국어 자막의 정확한 판독과 풍자 이해를 보장하지 않는다. 모델과 모델 revision을 고정하고 공식 예제의 입력 형식·점수 추출법을 따른다. 점수 척도가 다르므로 모델 간 점수를 직접 평균하거나 공통 임계값을 쓰지 않는다.

공식 자료: [BGE 모델 카드](https://huggingface.co/BAAI/bge-reranker-v2-m3), [Qwen3 텍스트 리랭커](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B), [Qwen3-VL 리랭커](https://huggingface.co/Qwen/Qwen3-VL-Reranker-2B), [Cohere Rerank 개요](https://docs.cohere.com/docs/rerank-overview).

## 3. 데이터 준비와 사람 평가

1. 실제 판결 30개와 사람이 승인한 이미지 코퍼스를 고정한다. 최종 headline·statement·확정 결과·강도·텍스트 버전 및 검색 query를 보존한다. 아직 writer 계약에 query가 없으므로 첫 실험에서는 사람이 작성하고 `query_source=human`으로 기록한다. 모델 생성 query 품질과 리랭킹 품질을 섞지 않는다.
2. 같은 사건의 mild/spicy/hell과 유사 패러프레이즈는 같은 그룹에 둔다. 사건 그룹 단위로 개발셋/보류 평가셋을 나눈다. 예: 서로 다른 사건 30개라면 20개/10개. 이미지 원본과 변형본도 같은 계열로 표시한다. 분할 후 보류셋으로 모델 지시문·임계값을 조정하지 않는다.
3. 작은 코퍼스는 모든 판결×이미지를 평가한다. 커지면 각 검색 방식의 후보 합집합과 의도적으로 만든 어려운 오답을 평가한다. 이때 Recall의 정답 분모는 판단한 pool 안에 한정되며 전체 코퍼스 Recall이라고 보고하지 않는다. 평가하지 않은 후보를 자동으로 0점 처리하지 말고 먼저 라벨링한다.
4. 모델 이름·점수를 숨기고 순서를 섞어 사람이 실제 이미지와 최종 판결을 함께 본다. 적합도는 0=부적절, 1=단어/소재만 유사, 2=상황·반응 적절, 3=농담·반전까지 정확. 자막 모순·판결 용도 위반은 별도 bool로 표시한다. 2 이상이면서 위반이 없는 후보를 적절한 집합으로 정의한다.
5. `fallback_preferred`는 어떤 이미지보다 기본 이미지가 나은 경우다. 가능하면 두 사람이 독립 평가한 뒤 불일치를 합의한다. 한 사람만 평가했다면 그 사실을 기록한다.

필수 사례: 배달/택시/구독 같은 소재 일치, 돈없음↔텅 빈 지갑 동의어, 유죄↔승인/축하 혼동, '돈이 없다'↔'돈이 많다' 자막 반대, 여러 컷의 반전, 자막 없는 이미지, 강도별 반응 차이, 과도한 조롱, 정답 없음, 동점, 최근 노출 전체/일부, 비공개·삭제·미승인 후보와 선택 직전 권한 철회.

평가 기록 형식의 예(가상 데이터이며 실제 정답표가 아니다):

```json
{
  "case_id": "delivery-001",
  "case_group": "delivery-001",
  "split": "dev",
  "intensity": "spicy",
  "text_version": 1,
  "verdict_tag": "GUILTY_LIGHT",
  "headline": "배달앱 VIP, 통장엔 방문객 없음",
  "statement": ["배달 주문을 반복해 예산을 소진했다."],
  "query_source": "human",
  "meme_query": {
    "situation": "반복 배달 주문으로 예산을 소진했다",
    "desired_reaction": "빈 지갑을 보고 현실을 부정하는 우스운 당황",
    "keywords": ["배달", "지갑", "현실부정"]
  },
  "fallback_preferred": false,
  "recent_image_ids": [],
  "judgments": [
    {"image_id": "wallet-denial", "grade": 3, "caption_contradiction": false},
    {"image_id": "spending-celebration", "grade": 0, "caption_contradiction": true}
  ]
}
```

검색 문서에는 v2 `search_text`와 해시를 사용한다. 원본 manifest의 상세 생성 프롬프트나 uncertainties를 긍정 검색 문장으로 넣지 않는다. 자산별 해시·metadata_version·검수/접근 상태를 별도 snapshot으로 고정한다. 로컬 pending 산출물을 승인 코퍼스로 자동 취급하지 않는다.

## 4. 통제된 실행 순서

1. **검색 평가:** 권한·용도 필터를 적용한 동일 코퍼스에서 태그/벡터 각각 20개(초기 실험 설정)를 수집하고 RRF(k=60)로 결합한다. 두 리스트의 합집합은 최대 40개다. 전체 코퍼스 크기가 작으면 전수 점수도 비교해 후보 누락을 진단한다.
2. **리랭커 비교:** RRF 상위 20개를 모든 모델에 똑같이 전달한다. 이 단계에서는 반복 노출 회피를 끄고 순수 순위를 비교한다. 이미지/텍스트 버전과 후보 순서를 고정한다. 동일 점수는 post_id·image_id 기반 고정 순서로 해소한다.
3. **쿼리 비교:** ① situation+desired_reaction+keywords, ② 여기에 최종 판결문을 더한 형태를 개발셋에서 비교한다. 지출 사실만 비슷한 후보를 낮추고 전달할 반응에 맞는 후보를 높이는 지시문은 별도 버전 파일로 고정한다. 태그 승인·권한은 지시문에 맡기지 않는다.
4. **멀티모달 효과:** 같은 VL 모델에 텍스트만 / 텍스트+실제 이미지를 각각 넣는다. 다른 모델끼리 비교한 차이를 이미지 입력 효과로 단정하지 않는다. 이미지 해상도와 리사이즈·자막 잘림 여부도 기록한다.
5. **선택 정책 평가:** 각 모델의 상위 5개에 동일 반복 노출 회피를 적용한다. 모두 최근 노출이면 1위를 선택한다. 폴백 임계값은 개발셋에서 모델별로 정하고 보류셋에서 한 번 검증한다. 최종 저장 전 권한/활성·버전 재검증은 공통이다.
6. **실패 주입:** 리랭커 timeout/오류/NaN/잘못된 candidate ID는 원래 RRF 순서로 복구한다. 벡터 장애는 키워드로, 전체 deadline 초과·유효 후보 부재는 결과별 기본 이미지로 복구한다. 예산과 잔여시간이 허용하는 일시 오류만 제한 재시도하고 실제 시도 비용도 집계한다.

11의 기본 목표는 추가 생성형 LLM 호출 없는 선택이다. 리랭커는 별도 추론 비용·지연을 추가하는 선택 기능이며, 사용자가 실험 결과를 보고 채택하기 전 기본 경로를 변경하지 않는다. 원격 API 실험은 데이터 반출과 비용 승인을 받은 뒤 수행한다. 이번 작업에서는 모델 다운로드·유료 호출을 실행하지 않는다.

## 5. 지표와 채택 조건

| 지표 | 계산·해석 |
|---|---|
| 후보 Recall@20, 최종 순위 Recall@5 | 상위 K의 적절 이미지 수 / 라벨된 적절 이미지 전체 수. 정답 없는 사례는 분모 제외하고 별도 건수 표시 |
| nDCG@5 | 사람 적합도 0~3의 순위 품질. gain=2^grade−1, discount=log2(rank+1). ideal DCG=0인 사례는 별도 보고 |
| 최종 적합 선택률 | 실제 선택이 적절 집합에 속하거나 fallback_preferred에서 기본 이미지를 선택한 사례 / 전체 사례 |
| 자막 모순·권한 위반 | 필터 전/후 후보 및 최종 선택 단계별 건수. 0건 요구 |
| 폴백 | 비율뿐 아니라 적절한 폴백/정답이 있는데 불필요한 폴백/필요한데 선택 강행을 분리 |
| 반복 노출 | 최근 노출 목록에 포함된 최종 이미지 비율. 품질 손실도 함께 비교 |
| 지연 | retrieval, embedding, rerank, 전체 선택 각각 p50/p95. cold와 warm 분리, batch·동시성·하드웨어 기록 |
| 자원·비용 | peak RAM/VRAM, query 임베딩 비용, 리랭킹 비용, 재시도 포함 판결당 총 비용. 로컬 실행은 API비 0과 서버 운영비를 구분 |

접근 위반/표시된 자막 모순 0건, 현재 방식 이상 최종 적합 선택률이라는 11 §9 게이트를 우선한다. 리랭커 채택은 RRF 단독 대비 품질 이득이 비용·지연에 비해 의미 있을 때만 한다. 모델별 timeout/비용 상한과 최소 품질 차이는 실행 전 제품 예산에 맞게 정한다. 실측 전 임의 숫자를 운영 상수로 넣지 않는다.

30개는 파일럿이다. 같은 사건 단위 paired bootstrap 신뢰구간 또는 판결별 승/무/패 표를 함께 보고, 차이가 불확실하면 더 단순하고 저렴한 방식을 유지하고 평가셋을 확장한다. 개발셋 최고 점수만으로 모델을 채택하지 않는다. 보류셋을 보고 수정했다면 새 보류셋이 필요하다.

## 6. M-series에서 실행할 때와 결과 보존

모델 실험용 환경은 서비스 의존성과 분리한다. 공식 예제의 CUDA/FlashAttention 설정을 M1에 그대로 복사하지 않는다. 먼저 설치된 PyTorch의 MPS 지원과 실제 모델 연산 호환성을 작은 배치로 검사하고, 지원하지 않는 연산은 원인과 CPU fallback을 기록한다. 0.6B부터 시작하되 메모리/지연을 실측하기 전 2B·8B 실행 가능성을 보장하지 않는다. 운영 서버가 다른 하드웨어라면 그 환경에서도 다시 측정한다.

재현 기록: 데이터 snapshot/분할/후보 해시, 모델 ID+revision, 라이브러리 lock, 지시문 버전, 문서·query 형식 버전, image preprocessing, batch·device·dtype·warmup·동시성, 원점수·정렬 결과·선택 이유·fallback 이유·단계별 시간·사용량. 모델 점수는 확률로 표시하지 않는다.

후속 실행기는 이 기록을 JSONL로 저장하고 같은 결과에서 지표를 재계산하도록 만든다. 지표 계산은 외부 호출 없이 테스트하고, 실제 모델 실행은 명시적 실측 명령으로 분리한다. 사용자 원문·로컬 이미지·세부 프롬프트가 담긴 결과는 일반 로그나 공개 저장소에 자동 올리지 않는다.
