# 골든케이스: LLM-SVG 방식 샘플

LLM이 짤을 보고 SVG로 다시 그리는 방식이 어디까지 가는지 보여주는 **손으로 그린
목표 샘플**이다. 아직 LLM 연동은 없다. 이 파일들은 두 가지 용도로 쓴다.

1. 실제 구현 시 few-shot 예시 (모델에게 "이 정도 톤으로 그려라"라고 보여줄 것)
2. 품질 기준선 — 모델 출력이 이보다 나쁘면 그 프롬프트/모델은 쓰지 않는다

## 무엇을 그렸나

현재 `--style doodle` 파이프라인의 실패 유형을 모두 덮도록 3장을 골랐다.

| 샘플 | 원본 | 현재 파이프라인 상태 |
| --- | --- | --- |
| `images-3.svg` | 거지왕 강림 (사람 얼굴) | Vision이 얼굴을 찾음 → 눈·코·입 있는 결과 |
| `images-11.svg` | 원숭이 2컷 | 얼굴 검출 실패 → 의미 없는 덩어리 |
| `images-9.svg` | 플랑크톤 (만화) | 얼굴 검출 실패 → 의미 없는 덩어리 |

## 구조: 모델은 그림만, 자막은 파이프라인이

SVG에는 **글자가 없다.** 자막은 렌더 단계에서 기존 `text_layer`의 OCR + 폰트
레이어로 합성한다. 한글 자막을 모델에게 path로 그리게 하면 반드시 뭉개지고,
자막 가독성은 타협 불가 요건이기 때문이다. 실제 구현도 이 분리를 지켜야 한다.

## 렌더

`cairosvg`는 이 샘플 렌더에만 필요하다 (native cairo 의존). 메인 파이프라인은
이 패키지 없이 동작하므로 `requirements.txt`에 넣지 않았다.

```bash
./venv/bin/pip install -r golden/requirements.txt
./venv/bin/python golden/render_golden.py
```

결과는 `golden/out/<이름>_golden.png` (투명 배경).

## 프롬프트에 반드시 들어가야 할 것

이 3장을 그리면서 각각 2~3번씩 다시 그렸다. 틀렸던 지점이 그대로 프롬프트 요건이 된다.

**1. 장면을 먼저 말로 옮기고 나서 그린다.**
첫 시도에서 플랑크톤이 든 **지갑을 건물로 잘못 읽었다.** 원본은 박음질이 있는
거대한 가죽 지갑인데 테두리 스티치를 초코바 톱니로 본 것이다. 그림이 아무리
좋아도 대상이 틀리면 밈이 아니다. 그래서 구현은 2단계로 간다 — 먼저 "누가 무엇을
들고 무엇을 하는 장면인지"를 텍스트로 뽑고, 그 서술을 근거로 SVG를 그리게 한다.

**2. 원본의 구도를 그대로 가져온다.**
원숭이 짤은 얼굴이 화면을 꽉 채우는 클로즈업인데, 처음에 작은 머리 + 어깨로
그렸더니 원숭이가 아니라 사람 흉상으로 보였다. 클로즈업은 클로즈업으로 그려야 한다.

**3. 형태보다 감정이 먼저다.**
"놀리는 느낌"은 이목구비를 정확히 옮긴다고 생기지 않는다. 윙크 + 히죽 올라간 입 +
아래에서 올라오는 손가락이 **같이** 있어야 산다. 프롬프트에서 표정을 형태가 아니라
감정으로 지정해야 한다.

**4. 자막 박스 좌표를 모델에게 알려준다.**
렌더 단계가 자막 영역의 획을 지우므로, 모델이 그 안에 그리면 그림이 잘린다.
실제로 첫 시도에서 "꺄☆핫" 영역이 원숭이 얼굴 윤곽을 잘라먹었다. 아래 칸 얼굴을
왼쪽으로 밀어 자리를 비우는 식으로 **구도가 자막을 피해야** 한다.

**5. 한 번에 나온다고 기대하지 않는다.**
사람이 원본을 보면서도 2~3회 고쳤다. 모델 1회 출력으로 이 품질을 기대하면 안 되고,
검증 게이트와 재시도가 전제되어야 한다.

## 비교에서 나온 결론

원본 / 현재 doodle / 골든 SVG를 나란히 놓고 보면 이득이 고르게 분포하지 않는다.

- **얼굴 검출이 실패하는 짤(동물·만화·옆모습)에서 이득이 압도적이다.** 지금은
  덩어리만 나오는데, 모델은 "정색한 원숭이", "플랑크톤이 건물을 미는 장면"처럼
  짤의 웃긴 지점 자체를 그릴 수 있다. 엣지 검출로는 도달할 수 없는 영역이다.
- **사람 얼굴이 잘 잡히는 짤에서는 이득이 작고, 오히려 손해일 수 있다.**
  `images-3`을 보면 골든 SVG가 더 깔끔하지만 더 평범하다. 현재 doodle의 멍한
  표정이 짤로서는 더 웃긴다. 즉 "LLM을 쓰면 무조건 낫다"가 아니다.

그래서 실제 구현 시 권장안은 전량 교체가 아니라 **폴백**이다.
얼굴 랜드마크가 잡히면 지금의 로컬 doodle을 쓰고, 검출이 실패한 짤에만
LLM-SVG를 태우면 비용과 비결정성을 실패 케이스에만 국한할 수 있다.

## 아직 결정되지 않은 것

- Provider와 모델 (설계 문서 D-06). API 키 없음
- 장당 비용·지연, 재시도 정책
- 모델 출력 검증 게이트: SVG 파싱 성공 / path 개수 상한 / 캔버스 밖 좌표 / 자막
  영역 침범 여부. 로컬 렌더러는 테스트로 잠갔지만 LLM 출력은 이런 게이트가 필요하다
- 대상 인식이 맞았는지는 자동으로 검증할 수 없다. 1단계 장면 서술을 사람이 훑는
  검수 단계가 필요하다 — 지갑을 건물로 그려도 게이트는 전부 통과한다
- 저작권(D-09): 재해석 정도가 커져 실질적 유사성은 낮아지는 방향이지만,
  자동으로 해소되지는 않는다
